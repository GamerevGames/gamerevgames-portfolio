Overview

Free Flow Combat is a third-person combat system built in Unity, inspired by the free flow combat system of the Batman: Arkham series. It lets players chain attacks fluidly across a group of enemies, with movement and combos that flow naturally from one hit to the next.

I built this project at University, starting with a proof-of-concept prototype, and developing it into a polished combat experience with impact effects, reactive enemies, and a small arena setting.

  • Smooth Attack Movement: the player glides to an attack position calculated from the camera angle and input direction.
  • Dynamic Targeting: attacks find and chain between enemies in the fight.
  • Impactful Feedback: shockwaves, particles, sound effects, and subtle camera shake on every hit.
  • Reactive Enemies: the attack type is passed to the enemy so it plays a matching reaction animation.
  • Clean and Modular Code: easy to understand and implement in existing projects.

How it works

Every attack moves through the same sequence of stages:

  1. Input. The input system reads the attack input along with the player's movement direction.
  2. Targeting. The system uses the camera angle and input direction to work out which enemy to engage and where the player should attack from and glide to.
  3. Movement. The player's position is smoothly interpolated to the calculated attack position using DOTween, closing the distance to the enemy so combos can chain across a group without breaking the flow of movement.
  4. Attack. The attack animation plays through Unity's Animator, with transition durations and interruption sources tuned so one attack cancels cleanly into the next.
  5. Impact. On contact, the hit triggers a shockwave, impact particles, a sound effect, and slight camera/screen shake.
  6. Reaction. The attack type is passed to the enemy's script, which selects a matching reaction animation.

Keeping each stage separate is what keeps the code modular and easy to follow.

Learning outcomes

Free Flow Combat taught me how much of a game's quality comes from game feel, not just mechanics. Comparing the first prototype to the final version, a handful of effects (impact particles, sound, screen shake, and reactive enemy animations) was enough to make it feel like an entirely different game.

It changed how I approach new projects: I now treat feedback and "juice" as part of the design from the start, rather than something to add at the end.

Challenges

Smooth transitions between attacks. Early on, some attacks felt clunky or disconnected because of timing mismatches and input buffering, which broke the fluid feel the system was meant to have.

Solution. I went delve further into Unity's Animator system and tuned parameters such as transition durations and interruption sources, so each attack could flow cleanly into the next.

Takeaway. This was more iterative refinement than a single major roadblock, but it showed me how much attention to detail separates a polished gameplay experience from a rough one.
